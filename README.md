
# Meteor Villager Roller 汉化版（村民刷附魔）

![checks](https://github.com/LeakDog/meteor-villager-roller-chinese/actions/workflows/checks.yml/badge.svg)
![release](https://github.com/LeakDog/meteor-villager-roller-chinese/actions/workflows/release.yml/badge.svg)

反复重置村民职业，直到刷出想要的附魔书。这是 [Meteor Client](https://github.com/MeteorDevelopment/meteor-client)
的附属模块（addon），面向在服务器上刷图书管理员附魔的场景。

本项目在汉化的基础上重写了提醒逻辑，新增了自动锁定交易与 QQ 推送，使得挂机刷附魔时
不必盯着屏幕。

## 版本要求

| Minecraft | Meteor | 状态 |
|-----------|--------|------|
| 26.2 | 26.2 | 支持 |

需要 Java 25。若要在旧版本 Minecraft 服务器上刷村民，请使用
[ViaFabricPlus](https://github.com/ViaVersion/ViaFabricPlus)。

本项目版本号独立起算，与上游的版本序列无关。

> 本模块与原版 Meteor Villager Roller 互斥，`fabric.mod.json` 中已声明 `breaks`。
> 两者注册同名模块会冲突，请只安装其中一个。

## 安装

从 [Releases](https://github.com/LeakDog/meteor-villager-roller-chinese/releases) 下载 jar，
放进 `mods` 目录，与 Meteor Client 同时安装即可。

## 字体限制（重要，请先读这一段）

Meteor 使用自绘字体渲染它自己的界面，而该字体只烘焙了 ASCII、拉丁、希腊和西里尔字形，
**不包含中日韩字符**。这是 Meteor 本身的限制，模块无法绕过。

因此：

- **设置界面里的中文会显示为空白** —— 包括设置描述、分组标题、按钮和弹窗。
  解决方法是在 Meteor 设置中关闭 `custom-font`，切换到原版字体。
- **聊天消息和屏幕通知的中文始终正常** —— 这两条路径走原版字体渲染，不受影响。

模块启用时会在聊天里提示一次这件事。

另外，设置项的内部名称（`name`）和分组名保持英文未改。Meteor 的配置以这些名称为键
存取，改名会导致玩家已有的配置全部失效。

## 使用方法

1. 准备一个村民（不能是傻子）
2. 准备若干讲台（32 个比较合适）
3. 建议准备一把斧头，品质越好刷取越快
4. 把自己和村民关在一个封闭空间里，除你们之外不要有其他可自由移动的实体或方块
5. 用半砖、方块、楼梯限制村民走动（**不要用活板门**，会干扰寻路）
6. 在村民能够到的位置放一个讲台，确认手动换职业可行
7. 按需配置模块并启用
8. 按聊天提示依次选择方块和村民
9. 让模块自己跑（若开启了「Pause on screens」，切出窗口会打开暂停菜单并暂停刷取）
10. 收工

## 功能说明

### 提醒

- 音效列表中的**全部**音效都会播放，而非只播第一个
- `sound-repeat-count` 重复轮数、`sound-repeat-delay` 间隔（tick），避免一次性提示被错过
- `show-toast` 弹出屏幕通知，切出游戏窗口后回来仍能看到
- 提醒先于模块关闭和自动断线执行，开启 `disconnect-when-found` 时也能收到完整提示
- 提示音由独立调度器播放，模块关闭甚至断线回到主菜单后，剩余轮数依然会播完
- 修正了音量与音调参数顺序写反的问题（此前两个滑块效果互换，且音量值被当作音调使用）

### 自动锁定交易（可选，默认关闭）

村民在**首次被交易后职业就永久固定**，之后再破坏工作方块也不会重置。所以刷到目标附魔时
立刻买下这本书，就能把结果保住，不必担心误操作或服务器重启导致白刷。

开启 `lock-trade` 后，刷到目标附魔时会自动用背包里的物品完成这笔交易。

| 设置 | 说明 |
|------|------|
| `lock-trade` | 总开关，默认**关闭**（此操作会消耗你的绿宝石和书） |
| `lock-trade-retry` | 锁定失败时保持模块开启并停在交易界面，便于补货后手动完成。默认开启 |

交易前会先做三项检查，不满足就不会白点：

- 该交易是否已售罄
- 背包里的绿宝石与书是否够支付（不足时会报出还差多少）
- 背包是否有空位放产出物

锁定结果对应三类 QQ 通知，可分别自定义：

| 设置 | 事件 | 默认 | 限流 |
|------|------|------|------|
| `onebot-msg-trade-locked` | 锁定成功 | 已启用 | 不限流 |
| `onebot-msg-trade-failed` | 锁定失败（售罄、背包满等） | 已启用 | 30 秒 |
| `onebot-msg-trade-insufficient` | 背包物品不足 | 已启用 | 30 秒 |

这三类额外支持 `{cost}` 占位符（实际支付的物品，如 `17 个绿宝石 + 1 个书`）和 `{reason}`
（失败的具体原因）。

注意：锁定成功后模块会保留交易界面不自动关闭，因为刚完成交易就关容器会打断服务端的取物处理。
你可以确认物品到手后自行关闭。

### 缺陷修复

对照上游 issue 排查并修复了以下问题：

- **交互包重发失控**：`interact-retry` 的计数器在到达阈值后不会清零，导致此后**每 tick 都发一个
  交互包**，很容易被服务器判定为异常。现在每次重发后重新计时。相关 issue：#37、#49
- **同一 tick 内重复交互**：射线未命中或交互未被消费时会立刻再发一个包。现在只发一次，
  重发统一交由 `interact-retry` 按间隔处理
- **配置损坏导致崩溃**：`Identifier.tryParse` 解析失败会返回 `null`，但原代码只在开启排序时
  清理无效条目，关掉排序就会在渲染设置界面和检查交易时抛 NPE。现在始终剔除
- **旧服崩溃**：经 Via 连接的旧版服务器可能不下发附魔注册表，原代码用 `lookupOrThrow`
  会把异常抛进网络线程。现在改为安全查询，取不到就跳过本轮并提示。相关 issue：#39
- **只能用讲台**：模块允许选择任意方块，但状态机里把讲台写死了三处判断，选其他方块会一直
  被判定为「放错方块」。现在按实际选定的方块判断，提示文字也会显示该方块名
- **村民消失后空转**：村民被杀、卸载或换维度后模块会持续空转。现在会检测并停止
- **「添加全部」含不可交易附魔**：`only-tradeable` 原本默认关闭，导致灵魂疾行、迅捷潜行、
  风爆这些村民不卖的附魔被加进列表。已改为默认开启（vanilla 的交易配方正是用
  `#minecraft:tradeable` 这个标签挑选附魔的）。若服务器有插件自定义附魔，请关掉此项。
  相关 issue：#15

### OneBot / QQ 推送（可选，默认关闭）

可通过 [OneBot v11](https://github.com/botuniverse/onebot-11) 协议把刷取过程中的各类事件
推送为 QQ 消息，可对接 [SnowLuma](https://github.com/SnowLuma/SnowLuma)、NapCat 等任意
OneBot v11 实现。除了刷到目标附魔，还能推送运行错误、状态异常、放置失败等情况，
每类消息都可自定义内容，也可单独关闭。

`OneBot` 设置分组：

| 设置 | 说明 |
|------|------|
| `onebot-enabled` | 总开关，默认关闭 |
| `onebot-url` | OneBot HTTP 服务地址，如 `http://127.0.0.1:3000` |
| `onebot-token` | access token，留空表示无鉴权 |
| `onebot-message-type` | `Private`（私聊）或 `Group`（群聊） |
| `onebot-target-id` | QQ 号或群号，纯数字 |

#### 通知类别与自定义消息

每类事件各有一个消息模板，**模板留空即表示不推送该类通知**。默认只开启「刷出目标附魔」
和「运行错误」两类，其余留空，避免挂机时被无关消息打扰。

| 设置 | 事件 | 默认 | 限流 |
|------|------|------|------|
| `onebot-msg-found` | 刷出目标附魔 | 已启用 | 不限流 |
| `onebot-msg-error` | 运行错误导致中止 | 已启用 | 30 秒 |
| `onebot-msg-started` | 开始刷取 | 留空 | 不限流 |
| `onebot-msg-stopped` | 刷取停止 | 留空 | 不限流 |
| `onebot-msg-place-failed` | 放置失败、快捷栏缺方块 | 留空 | 1 分钟 |
| `onebot-msg-anomaly` | 状态异常（放置被撤销、放错方块等） | 留空 | 1 分钟 |
| `onebot-msg-profession-timeout` | 村民未按时接受职业 | 留空 | 1 分钟 |

可用占位符：

| 占位符 | 含义 | 可用于 |
|--------|------|--------|
| `{player}` | 玩家名 | 全部 |
| `{server}` | 服务器地址 | 全部 |
| `{enchant}` | 附魔名 | 刷出目标附魔 |
| `{level}` | 附魔等级 | 刷出目标附魔 |
| `{price}` | 价格（绿宝石） | 刷出目标附魔 |
| `{reason}` | 具体原因 | 运行错误、放置失败、状态异常 |

例如把 `onebot-msg-found` 写成：

```
{player} 在 {server} 刷到了 {enchant} {level} 级，只要 {price} 个绿宝石
```

写错的占位符会原样保留在消息里，方便你发现拼错了。点**预览消息模板**可以在聊天里看到
各类消息填好占位符后的样子，不会真的推送。

**关于限流**：状态异常和放置失败这类事件可能每 tick 都触发，若不限流会瞬间刷爆消息、
甚至触发 QQ 风控。所以这些类别有最小发送间隔，且同类别内容重复时也会被抑制。
模块重新启用时限流记录会清空。

启用后，模块设置面板顶部会出现「OneBot 连接」区块。点击**测试连接并发送 ping** 会先调用
`get_login_info` 验证地址与 token（成功时回显机器人账号），再向配置的目标实际发送一条 ping
消息。分两步是为了把「地址或凭证有问题」和「目标 ID 或发送权限有问题」区分开。

失败时会给出具体原因：无法连接（地址或端口错）、鉴权失败（token 错）、retcode 非零
（附带服务端说明，例如群不存在）、响应不是合法 JSON（可能不是 OneBot v11 服务）等。

#### 对接 SnowLuma

SnowLuma 默认就带一个 HTTP 服务端，配置为 `127.0.0.1:3000`、路径 `/`，并会在首次启动时
**随机生成一个 access token**。所以通常只需：

1. 在 WebUI（默认 `http://localhost:5099`）里完成 QQ 接入
2. 确认名为 `http-default` 的 HTTP 服务端处于启用状态，并复制它的 accessToken
3. `onebot-url` 填 `http://127.0.0.1:3000`，`onebot-token` 粘贴刚复制的值

注意 token 不能留空 —— SnowLuma 既然默认生成了一个，就必须填对应的值，否则一律返回 401。
若你在 WebUI 里改过 `path`（例如改成 `/onebot`），则 `onebot-url` 要写成
`http://127.0.0.1:3000/onebot`。

安全须知：

- 这是**出网行为**，会把附魔名、等级、价格以及（若启用相应类别）错误原因发送到你自己配置的端点。默认关闭，需显式填写配置才会触发。
- `onebot-token` 是凭证，会随 Meteor 配置以**明文**保存在本地，但不会出现在任何聊天消息或日志中。
- 建议只填本机回环地址（`127.0.0.1`）。若填公网 `http://` 地址，token 与消息内容均为明文传输。
- 请求异步执行，网络故障只会在聊天里报一条错误，不会阻塞游戏或影响刷取逻辑。

## 已知限制

模块只处理图书管理员的附魔书交易，不支持其他职业或交易类型。

自动锁定交易只在服务器上验证过流程逻辑，实际行为受服务端插件与反作弊影响。首次使用
建议先在不重要的村民上试一次。

常见问题：

- **提示「已锁定你的村民」两次后停止** —— 模块是为服务器设计的。单人游戏和某些插件会改变
  交易界面的行为，无法处理。
- **无法再与村民交互** —— 同上，界面不同步可以通过重进服务器解决。
- **不放回讲台** —— 会放回。失败说明该位置已被玩家、村民、其他实体或方块占据。
  刷取会暂停，手动放置方块后自行恢复。
- **刷取时会关闭聊天和其他界面** —— 无法避免。请求与村民交互时服务器会强制客户端打开交易
  界面并替换当前界面，而打开该界面是获取交易列表的前提。开启「Pause on screens」可以在有
  界面打开时阻止新的交互，处理完后手动与村民交互即可继续。
- **讲台用完后不会自动捡回** —— 寻路并移动到地面物品既复杂又容易出错。可以用漏斗、
  投掷器或流水来优化收集。
